# Clone Rendering Blockers — Status as of 2026-04-13

## Where We Got To

The clone pipeline works well through Stage 1 (clone) and Stage 2 (componentize + strip). The issue is **rendering the componentized theme in a Next.js site** — the clone's CSS doesn't load correctly.

### What Works

1. **Clone stage** — high fidelity. Opening `output/clones/corvus/html/pages/home.html` directly in a browser looks nearly identical to colorcode.events, including animations.
2. **Componentize pass** — preserves clone JSX as React components. HomePage.tsx is 1,122 lines of real markup.
3. **Strip pass** — replaces 107 content props across 5 pages + header. Business text, headings, paragraphs, images stripped correctly.
4. **Brief auto-discovery** — `--clone corvus` auto-finds matching brief from `output/briefs/`.
5. **Image stripping** — broadened to catch `images/` paths (not just `assets/images/`) and alt attributes.

### What Doesn't Work: CSS Loading in Next.js

The clone's HTML uses **Breakdance CSS classes** (`bde-section-17-100`, `bde-div-18-109`, `.breakdance`, `.callout`, `.graphic`, etc.). The CSS rules for these classes exist in 53 downloaded files at `output/clones/corvus/assets/css/`. The problem is getting them to render in a Next.js site.

**Attempts and failures:**

1. **Concatenate all CSS into globals.css** — Some files (`rsvp.css`, `square.css`) have CSS syntax that Turbopack's parser rejects (complex selectors, inline SVG data URIs).

2. **Filter to essential CSS only** — Removed plugin CSS, kept 26 Breakdance layout files. One file (`global-settings.css`) has `url(icons/eye.svg)` — a relative path that Turbopack tries to resolve as a module import. Fixed with `sed` to strip it.

3. **`@import "../theme-system/dist/base.css"`** — Generated by extract-theme but doesn't exist. Working themes (orion/vega) don't import this at all.

4. **Tailwind Preflight reset** — `@tailwind base;` in globals.css applies a CSS reset that overrides Breakdance's typography, heading sizes, body colors, and layout. Removing `@tailwind base;` and `@tailwind components;` was the last attempt — result still showed no layout.

### Root Cause Analysis

The fundamental issue is that **Breakdance CSS was designed to work in a WordPress environment**, not in a Next.js/Tailwind pipeline. Specific conflicts:

- **CSS processing pipeline**: Tailwind/PostCSS processes globals.css and may transform or strip non-Tailwind CSS. Breakdance CSS needs to be loaded raw.
- **Turbopack CSS parsing**: Stricter than browser CSS parsing — rejects syntax that browsers accept (complex selectors, relative `url()` references, minified mega-lines).
- **CSS specificity wars**: Breakdance uses `!important` heavily and expects to be the only CSS framework. Tailwind's reset layer conflicts.
- **Asset resolution**: Breakdance CSS references assets via relative paths (`url(icons/eye.svg)`) that don't exist in the Next.js project structure.
- **Font loading**: Breakdance loads custom fonts (Aeonik) via CSS `@font-face` in `custom_font_aeonik.css` — these font files need to be in the right location.

### What Needs to Happen

The CSS problem has a few possible solutions to explore:

**Option A: Load clone CSS via `<link>` tag, not Tailwind import**

- Copy the filtered/fixed CSS files to `public/css/`
- Add `<link rel="stylesheet" href="/css/breakdance-combined.css" />` in layout.tsx `<head>`
- This bypasses Tailwind/PostCSS entirely — the browser loads it as raw CSS
- Tailwind is only used for theme tokens, not for layout

**Option B: Use `dangerouslySetInnerHTML` for a `<style>` tag**

- Inline the Breakdance CSS as a raw `<style>` block in layout.tsx
- Bypasses PostCSS but increases HTML size

**Option C: Rethink the approach**

- Instead of preserving Breakdance CSS classes, convert them to inline styles or Tailwind classes during the componentize pass
- Much harder but produces a more portable result

**Option D: Pre-process the clone CSS**

- Run the Breakdance CSS through a sanitizer that:
  - Removes `url()` references to missing assets
  - Splits mega-lines into separate rules (Turbopack line length issue)
  - Strips rules for unused selectors (WooCommerce, tickets, etc.)
  - Ensures all syntax is Turbopack-compatible
