# Pipeline Theme Wiring & Example Pages

**Date:** 2026-02-22 → 2026-02-23
**Branch:** `feature/pipeline-theme-wiring`
**Status:** Completed

## Objective

Wire the ingestion pipeline so that test sites (test-lyra, test-atlas) use their own generated theme registries and example pages instead of falling back to vega defaults. Then overlay the generated example pages onto the test sites with bare shell layouts.

## What Changed

### Phase 1: Registry Wiring (YOLO brief: pipeline-theme-wiring)

**Problem:** Generated theme packages exported a `DeepPartialThemeConfig` but not a `ComponentRegistry`. Test sites fell back to `vegaRegistry` because there was nothing else to import.

**Fix:**

- `tools/scaffold-theme-package.ts` — Added `REGISTRY_PRESETS` constant mapping base themes (vega/orion) to variant presets. The generated `index.ts` now exports a typed `ComponentRegistry` alongside the config.
- `packages/themes/lyra/index.ts` — Added `lyraRegistry` export
- `packages/themes/atlas/index.ts` — Added `atlasRegistry` export
- `sites/test-lyra/theme.config.ts` + `layout.tsx` — Rewired to `lyraRegistry`
- `sites/test-atlas/theme.config.ts` + `layout.tsx` — Rewired to `atlasRegistry`
- `.claude/commands/pipeline.ingest.md` — Simplified Step 5a to single template (no orion/vega branching), added Step 5e for layout.tsx wiring

### Phase 2: Example Pages & Bare Shell (YOLO brief: pipeline-example-pages)

**Problem:** Test sites still used base-template's full layout (SiteHeader, Footer, PageShell, analytics) which conflicted with generated example pages that include their own nav/footer components.

**Fix:**

- Bare shell `layout.tsx` for both test sites — only `ThemeProvider` context, no SiteHeader/Footer/PageShell/analytics/consent/geo
- Overlaid example pages from `output/ingestion/{lyra,atlas}/example-pages/app/` into test site `app/` directories
- `.claude/commands/pipeline.ingest.md` — Added Steps 5e (bare shell), 5f (example page overlay with hard-fail gate), 5g (visual comparison spec)
- `tools/lib/pipeline-visual-compare.ts` — New sharp-based pixel diff utility
- `sites/test-{lyra,atlas}/e2e/visual-compare.spec.ts` — Playwright specs for visual comparison

### Phase 3: Runtime Fix-ups (interactive debugging)

**Problems discovered when running dev servers:**

1. **Lyra barrel file had 3 phantom exports** — referenced files (`cta-colorcode-buffalo-tickets-comi`, `cta-subscribe-to-our-newsletter`, `navigation-jump-to`) that were never generated by the pipeline. Removed from `packages/themes/lyra/components/index.ts`.

2. **Animation import path double `src/`** — All 38 lyra + 21 atlas generated components imported from `@platform/core-components/src/components/animation`. But tsconfig maps `@platform/core-components/*` → `../../packages/core-components/src/*`, creating `src/src/`. Fixed all 59 files to use `@platform/core-components/components/animation`. Also added explicit `"./components/animation"` export to `packages/core-components/package.json` (the glob pattern only matches `.tsx` index files, but animation has `.ts`).

3. **Atlas barrel file only exported 1 of 46 components** — `DirectoryListing` was the sole export. Built out full barrel with 33 unique exports mapped to canonical source files.

4. **16 atlas components missing RevealOnScroll import** — Used `<RevealOnScroll>` in JSX without importing it. Added missing import to all 16 files.

5. **SiteHeader with no props on 4 ticket pages** — Pipeline generated `<SiteHeader />` as a fallback for non-existent `navigation-jump-to` component. `SiteHeader` requires a nav items array prop, so calling it bare crashes with `.map()` on undefined. Removed from both lyra and atlas ticket pages.

## Known Issues / Follow-up Work

### Pipeline Component Quality (separate session)

- Generated components use `props['kebab-case']` instead of `props.camelCase` — props are never populated
- Nav links use placeholder/undefined `href` values — clicking does nothing
- Some components are near-duplicates with slightly different names

### Pipeline Crawling Depth (separate session)

- Atlas was ingested from `https://themes.boldway.agency/deep/bold/` which is a directory index page
- Only 1 page was analyzed — the homepage is literally a file listing
- **Recommendation:** Support a URL manifest (list of specific URLs to crawl) rather than relying solely on root URL + link discovery. User should be able to specify exactly which pages represent the theme.

### Turbopack theme.config Resolution (low priority)

- `tailwind.config.ts` can't resolve `./theme.config` under Turbopack
- Affects CSS variable injection via the theme plugin, but inline `theme.extend.colors` and theme `globals.css` partially compensate
- All production sites use webpack (next build), not Turbopack, so this only affects dev mode
