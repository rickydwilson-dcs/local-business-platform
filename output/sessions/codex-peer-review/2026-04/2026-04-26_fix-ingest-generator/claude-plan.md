## Phase 2 — Generator: `needsUseClient()` fix (Bug 1)

### Step 2.1 — Remove blanket Navigation category rule

**File:** `tools/lib/theme-component-generator.ts:371`

Delete one line:

```typescript
if (blueprint.category === "Navigation") return true;
```

**Rationale:** The `CLIENT_PATTERNS` regex (line 358) matches `onClick`, `onChange`, `useState`, `useEffect`, `onMouseEnter`, etc. Any real interactive nav component will contain one of these and will still be marked as client. The only components that lose the `"use client"` directive are pure-static navs (announcement bars, breadcrumb strips) — which should always have been Server Components.

**Risk:** If a navigation blueprint generates JSX with interactive patterns that somehow don't match `CLIENT_PATTERNS`, it would become a Server Component and fail at runtime when that component tries to use browser APIs. Mitigation: `CLIENT_PATTERNS` is broad enough (includes `RevealOnScroll`, `Carousel`, `IntersectionObserver`) that this edge case is very unlikely.

**Does not affect existing themes:** orion, vega, cygnus, solaris were hand-written, not generated by this function.

**Verification gate:** `pnpm type-check` passes. The existing `needsUseClient` test (if any) must still pass.

```typescript
function hexToRgba(hex: string, alpha: number): string {
  const h = hex.replace("#", "");
  const r = parseInt(h.slice(0, 2), 16);
  const g = parseInt(h.slice(2, 4), 16);
  const b = parseInt(h.slice(4, 6), 16);
  return `rgba(${r},${g},${b},${alpha})`;
}
```

**File:** `tools/scaffold-theme-package.ts` — inside `generateComponentBarrel()`, before `return lines.join('\n')`

```typescript

let primaryFooterBp: SectionBlueprint | undefined;

for (const bp of analysis.sectionBlueprints) {
  const conf = componentMatches?.get(bp.id)?.matchConfidence;

if (primaryFooterBp) {
```

**Edge case — no unmatched Nav/Footer:** If all navigation blueprints are matched to core (exact/close), `primaryNavBp` is undefined and no alias is added. This is acceptable — if no nav component was generated, there's nothing to alias. The pipeline runs after the generator, and TPV-002 would still flag it; but that's a different problem (no nav blueprint generated at all, which is rare).

**Ordering logic:** Using the first unmatched Nav blueprint means announcement bars (which often come first in the blueprint list) could become the `Header` alias. This is a potential issue. Better approach: prefer the blueprint whose `componentFileName` contains `site-header` or whose `purpose` contains "sticky" / "primary navigation". If that's not found, fall back to the first Nav blueprint.

Revised primary nav selection:

```typescript
for (const bp of analysis.sectionBlueprints) {
  const conf = componentMatches?.get(bp.id)?.matchConfidence;
  const isMatched = conf === "exact" || conf === "close";
  if (!isMatched && bp.category === "Navigation") {
    const fn = bp.componentFileName.toLowerCase();
    const pur = bp.purpose.toLowerCase();
    const isMainNav =
      fn.includes("site-header") ||
      fn.includes("nav-bar") ||
      fn.includes("primary-nav") ||
      pur.includes("primary") ||
      pur.includes("sticky") ||
      pur.includes("main nav");
    if (isMainNav && !primaryNavBp) {
      primaryNavBp = bp;
      break;
    }
    if (!primaryNavBp) primaryNavBp = bp; // first-found fallback
  }
  if (!isMatched && bp.category === "Footer" && !primaryFooterBp) primaryFooterBp = bp;
}
```

## Risks and Trade-offs

| Risk                                                                               | Likelihood | Mitigation                                                                                                    |
| ---------------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------- |
| Announcement bar selected as `LyraHeader` alias                                    | Medium     | Use filename/purpose heuristic to prefer the "main" nav component                                             |
| Existing `site-analysis.json` files break when read by patched scaffold            | Low        | `blueprintId` is optional; fallback name-match logic preserved                                                |
| `hexToRgba` breaks on non-6-digit hex (shorthand, rgba)                            | Low        | Guard with regex before calling                                                                               |
| Removing Navigation category rule causes unexpected Server Components              | Low        | `CLIENT_PATTERNS` regex covers all real interactive patterns                                                  |
| `DEFAULT_TYPOGRAPHY_SCALE` values don't match what a specific theme actually needs | Low        | Per-site typography is tuned in `theme.config.ts` overrides; the DefaultConfig scale is a baseline, not final |
