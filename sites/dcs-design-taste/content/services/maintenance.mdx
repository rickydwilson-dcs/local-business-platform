## Keeping your site healthy after launch

A site that doesn't get maintained gets slower, less secure, and eventually breaks. Dependency vulnerabilities accumulate. APIs deprecate. Next.js releases security patches. Without someone watching these, problems compound.

### What we monitor

**Uptime** — we check every site every 60 seconds from three UK locations. If a site goes down you're notified within two minutes. If it's a known issue we're already working on it.

**Performance** — Core Web Vitals are measured weekly. If LCP or CLS degrades — typically because of a new image or a third-party script — we flag it before it affects rankings.

**Security** — we subscribe to the Node.js security feed, npm advisory database, and Next.js security announcements. Patches are staged and deployed on a structured cycle.

**Dependencies** — Dependabot runs on every repository. Updates are reviewed, tested, and batched into the fortnightly sprint rather than deployed individually, which reduces the risk of a breaking change slipping through.

### Support

Support requests come in via a shared Slack channel or email. Priority issues — anything affecting the site's ability to function or transact — jump to the front of the queue.

We document what we do. You always know what changed and why.
